# AGENTS.md

AI エージェント（Claude Code / Codex CLI など）に常時適用する共通ルール。
状況依存の詳細は各 Skill に切り出してある（末尾の「詳細は Skill を参照」を見よ）。

## 言語
- 会話・回答・レポートはすべて日本語で行う。
- コミットメッセージは英語で、1行で簡潔に書く。

## 進め方
- 着手する前にタスクを細かく分解して提示する。
- 「調査する」「特定する」「説明する」依頼のときは、勝手にファイルや設定を変更しない。変更は明示的な依頼、または提示して承認を得たあとに行う。
- 修正内容だけでなく、その理由や仕組みも簡潔に添えて説明する。

## スコープ・設計
- 依頼されていない作業（i18n 対応など）を勝手に足さない。スコープは絞る。
- 既存の実装・規約に合わせる。
- 1 箇所でしか使わない抽象化（ラッパー・定数など）は作らない。

## 安全性
- `rm` などの破壊的コマンドをスクリプトへ安易に入れない。必要なときは明示的に確認する。
- `git push` など外向き・不可逆な操作は事前に確認する。

## コード・成果物
- 使い捨てのスクリプトやツールは Python でなく Ruby を使う（細かいスタイルは問わない）。
- ドキュメントなどの成果物は、作業ディレクトリの直下に `.md` で出力する。
- すべてのファイルの末尾には必ず改行を入れる。

## ルールの育て方（メタルール）
- 今後一般的に適用できそうな指示を受けても、その都度は確認しない。
- 作業が一段落した段階で、それらをまとめて「標準ルールにするか」を確認する。
- YES なら、常時効くものはこの AGENTS.md に、状況依存の詳細は該当する Skill に追記する。

## 詳細は Skill を参照
- 環境・ツール（シェル / asdf / ghq / Neovim / Docker / dotfiles 運用）→ `dev-environment`
- Ruby ソースコードを書くときの規約 → `ruby-source`
- Git 運用（ブランチ / コミット / push / モノレポ）→ `git-workflow`
- 検証と成果物のスタイル（lint・typecheck・ブラウザ確認・ドキュメント形式）→ `deliverable-and-verify`
